# 使用者確認的盤點與網頁來源的 AI 評級（2026-11-21，計畫 T67）

> 狀態：使用者 2026-11-21 看過盤點，**全部照建議定**（含第 9 項：測試全過就由主持者部署並跑實測）。這份文件改掉的既有決定列在第 8 章。

## 0. 起因

### 0.1 使用者說的

- 看 M8（MU 定期審查）的結果時，問到網址白名單：「DRAMeXchange 明顯是因為 MU 才出現，未來其他股票可能又會有其他，我們不可能去枚舉這些網址。」
- 我提「每檔的 `webSources.domains` 由你同意」之後，使用者說：「我自己是沒有相關知識，能夠去判斷哪些網站可以用，哪些是內容農場，這些網站其實都是 AI 找的，它自己其實應該就可以判斷。」
- 接著請我盤點「目前很多需要我確認的，看還有哪些其實並不需要我去確認」。

### 0.2 判斷標準（使用者同意）

只有下面四種要使用者確認：

1. **真的動錢**：下單由使用者在券商做，所以照做或不做要他回覆；入出金、補差額。
2. **只有他知道的事**：快照的實際股數與現金。
3. **他的意圖或偏好**：這檔算自選還是動能、要不要冒這個險、他**親手寫**的出場條件被 AI 改寫之後是不是他的意思。
4. **改已經定好的設計**。

其他要他判斷專業內容的確認（這個網站可不可信、這條前提寫得好不好、這個門檻合不合理），他沒有依據判斷，只會變成照按，是假的把關。這類改成：程式檢查、和引用的人分開的另一個 AI 角色、事後分開記成績。

## 1. 網頁來源：AI 評級（X4、X7；取代 `web_evidence` §1.3 的清單與每檔的 `domains`）

### 1.1 原則

1. **讀和信分開。** 分析師需要什麼就取什麼；能不能拿來判前提、確認條件，看網域的級別。
2. **評級的不是引用的人。** 分析師想引用一頁，又由它決定那一頁可信，會偏向算可信。評級交給另一個子代理「來源評級」。
3. **評級不看網頁內文。** 只看網域、網站自稱的名稱（Worker 從 `og:site_name` 或 `<title>` 取，最多 60 字）。網頁可以自稱權威、夾帶給 AI 的指示；不看內文就影響不了評級。
4. **評一次、存起來、所有股票共用。** 同一個網域不每次重評（避免這次可信、下次不可信）。
5. **人寫的種子優先。** `webSources.ts` 現有的清單變成「種子」，種子的級別不會被 AI 改；使用者說某個網域不對，主持者改種子。
6. **排除列表照舊**（`WEB_EXCLUDED`：fool.com、stocktwits.com、seekingalpha.com…）：不抓、評不上去。

### 1.2 級別

| 級別 | 是什麼 | 誰給 |
|---|---|---|
| `PRIMARY` 一手 | 發布者就是當事人或統計機關：公司與同業的新聞室、投資人關係網站、交易所、政府統計、央行 | 種子或 AI |
| `NAMED` 產業研究機構 | 公開新聞稿與報價摘要的產業研究機構（TrendForce 這類） | 種子或 AI |
| `MEDIA` 媒體 | 有編輯、會寫明消息來源的新聞媒體與產業媒體 | 種子或 AI |
| `LEAD` 只當線索 | AI 評過但不夠格（部落格、聚合站、內容農場、看不出是誰）；或還沒評的（`UNRATED`） | AI／預設 |
| 排除 | `WEB_EXCLUDED`，以及 AI 評成 `EXCLUDE` 的 | 種子或 AI |

能觸發什麼照 `web_evidence` §1.6 的表，只是「清單內的級別」改成「這個網域現在的級別」：`PRIMARY`、`NAMED` 可以判前提不成立；`MEDIA` 判前提不成立要三票各自引用 2 個不同網域；`LEAD`、`UNRATED` 一律只當線索（可以寫進摘要、新風險、「要看的事」，不能當判前提或確認條件的引用）。`RAISE` 與回到標準照舊要至少一條申報或財報引用。

### 1.3 抓取（改 `web_evidence` §1.4 的第一條規則）

- 網域不在排除列表、是公開的 `https` 主機，就抓（不再要求在清單內）。其他規則不變：逾時、2 MB、轉址每一站也要不在排除列表、只收 HTML、內文少於 1,500 字算 `THIN`、要認得出發布日、發布日 ≤ 決策日、太舊的 `TOO_OLD`、同一個網站一次最多 4 篇、一次執行最多 8 份 60,000 字。
- **路徑限制**：種子的 `paths` 只在**有明確理由**的留著，改名 `onlyPaths`：
  - `federalreserve.gov`、`bls.gov`：留（會議紀錄的網址日期是開會日，不是發布日；其他頁面的日期認法不同）。
  - `trendforce.com`：改成「不收」的路徑 `skipPaths: ['/research/']`（付費報告頁只有摘要）。
  - `dramexchange.com`、`nvidianews.nvidia.com`、`finance.yahoo.com`：拿掉。報價頁、列表頁多半認不出發布日或內文太短，已經會被 `NO_DATE`／`THIN` 擋下。Yahoo 的 `/markets/…/articles/` 文章就是這次 M7 被擋的那種。
  - AI 評的網域沒有路徑限制。
- `NOT_LISTED` 只剩兩種原因：`EXCLUDED`（排除列表）、`PATH`（種子的 `onlyPaths`／`skipPaths`）。

### 1.4 評級怎麼做

**時機**：在同一次執行裡，取文件之後、三票之前。Worker 的取文件回應（`/ai/task/<id>/docs`）每份文件多帶 `domain` 與 `rating`（`PRIMARY`／`NAMED`／`MEDIA`／`LEAD`／`UNRATED`）。有 `UNRATED` 的，主代理開一個新的子代理「來源評級」。

**來源評級拿到的**：只有網域與 Worker 取的網站名稱的清單（新端點 `GET /ai/task/<id>/unrated` 回 `[{ domain, site_name }]`）。**不給**網頁內文、標題、分析師的理由。

**它送回的**（新端點 `POST /ai/task/<id>/ratings`，和取文件同一把金鑰、同樣只在任務開著時能用）：

```json
{ "role": "來源評級",
  "ratings": [ { "domain": "dramexchange.com", "tier": "NAMED", "reason": "TrendForce 旗下的記憶體報價網站，公開週報與合約價" } ] }
```

- `tier` 是 `PRIMARY`、`NAMED`、`MEDIA`、`LEAD`、`EXCLUDE` 其中之一；`reason` 一句，100 字以內。
- 程式檢查：網域要是這次 `/unrated` 給過的；種子與排除列表裡的不收（回 `refused`）；一次最多 12 個。
- 寫進新表 `web_source_ratings`（下面），之後所有股票、所有執行都用。

**判的時候用哪個級別**：Worker 收到結果、跑 `check.ts` 與 `reviewDecision` 時，用**當下**的級別（所以同一次執行裡剛評好的就算數）。存進 `ai_runs.added_docs` 的每份文件多記 `rating`（判的時候用的那個），之後重看紀錄對得上。

**這一步寫在哪**：新檔 `ai/prompts/source_rating.md`，由會取文件的四個功能 prompt 指到它（「取完文件、還有 `UNRATED` 的話，照 `ai/prompts/source_rating.md` 開來源評級」）。**`run.md` 不用改**（不用重貼排程），因為功能 prompt 是從 repo 讀的，新端點也寫在 `source_rating.md` 裡。四個 prompt 升版：`own_review_v5`、`own_drop_v5`、`own_draft_v3`、`market_brief_v2`。

**做不到的事寫清楚**：程式分不出「來源評級」和分析師是不是真的不同的子代理，只能從執行紀錄（`process` 裡的角色）看；評級和引用是同一家的模型，系統性的偏差擋不掉。底線照舊：`LEAD` 不能動檔位、`MEDIA` 要兩個網域、`RAISE` 要申報。

### 1.5 `web_source_ratings`（新表，只增加）

| 欄位 | 說明 |
|---|---|
| `domain` | 主鍵，小寫、去掉 `www.` |
| `tier` | `PRIMARY`／`NAMED`／`MEDIA`／`LEAD`／`EXCLUDE` |
| `site_name` | Worker 取的網站名稱 |
| `reason` | 評級的一句理由 |
| `run_id` | 哪一次執行評的 |
| `rated_at` | |

- 種子不寫進這張表（種子在程式裡，查級別時先看排除、再看種子、再看這張表，都沒有是 `UNRATED`）。
- 不會自動重評。種子改了以種子為準。

### 1.6 條件的 `confirm_by: web:<網域>`（X4）

- 改寫（`own_check`）、草稿（`own_draft_v3`）、審查建議的條件都可以寫 `web:<網域>`，**不再要求網域在清單或這檔的 `domains` 裡**（只擋排除列表）。
- 審查時用它確認條件成立（甲類）：照舊要三票引用**那個網域**的文件，而且那個網域當下的級別要是 `PRIMARY` 或 `NAMED`；`MEDIA` 照舊不行；還沒評或 `LEAD` 的不算，那一票改成這一條證據不足。
- 勾選條件時選來源的選單拿掉（持股頁、確認改寫的頁面）。顯示照舊寫「審查時用 <網站名稱> 的網頁檢查」，後面加級別（「產業研究機構」）；還沒評的寫「（來源還沒評級，評級之前不算數）」。

### 1.7 每檔的 `webSources`

- `domains` 拿掉：抓取、取文件、條件來源都不再看它。已經存的（目前只有 MU）留在資料裡不讀。
- `peers` 留著（同業的 EDGAR 申報與 Yahoo RSS，§1.2 的 S1、S2），改由草稿直接帶入（§2.3）。編輯論點頁的「同業」欄照舊可以改（意圖）。
- 存檔前的試抓（`/api/ops/own-sources/probe`）只剩同業：核對 EDGAR 代號存在。

### 1.8 顯示與運作統計

- 審查紀錄頁「AI 這次取回的文件」每份多寫級別；剛評好的寫「（這次評的：<理由>）」。
- 運作統計多一段「網頁來源的評級」：每個 AI 評過的網域、級別、理由、評的日期、被引用幾次。使用者不必看；覺得哪個不對就說，主持者改種子。
- 原本「最近 90 天被略過最多的網域」改成「被排除或路徑不收的網址」（`NOT_LISTED` 只剩這兩種）。

## 2. 草稿：一鍵採用（X1、X2、X3；改 `web_evidence` §2.3）

### 2.1 畫面

編輯論點頁有 `READY` 的草稿時，那一塊的順序：

1. **反方三點**與「今天沒有持股會不會買」的答案（照舊放最上面）。
2. 草稿的論點、前提（每條的「怎樣算證實」「怎樣算不成立」「用什麼查」或「信念」）、出場條件、同業：**只顯示**，沒有勾選框。
3. 兩個按鈕：**「採用這份草稿」**、「不用這份草稿」（照舊）。

「採用這份草稿」= 整份照草稿存檔（論點、全部前提、全部出場條件、同業），存完回到持股頁，畫面寫「已採用 M/D 的草稿；要改字在這一頁改」。之後要改字就用原本的編輯論點流程（記成 `USER`）。

- 按鈕旁一行字：「採用之前看一眼最上面的反方三點：還願意抱著這檔嗎？」（不需要專業知識，只問意願。）
- 前提剛被判不成立之後寫的草稿（§2.4 第 6 點）：最上面那句警告照舊；採用照舊算一次「失效後修改」並計次；`keep_id` 不能是被判不成立的那條（程式照舊擋）。
- 現有論點和草稿不同時，採用前照舊顯示對照（哪幾條前提會被換掉、沿用哪幾條）；這一步不加勾選，只多一個「確定採用」。

### 2.2 出場條件不再過第二關（X3）

- `own_draft_v3`：`EVENT` 條件的 `check` 寫成和 `own_check` 一樣的格式（`{ "confirm_by": [...] }`，`8-K`／`10-Q`／`10-K`／`SEC`／`earnings_call`／`major_news`／`web:<網域>`）；`XBRL` 條件照舊；`PRICE` 照舊只記錄。
- 程式檢查用 `own_check` 送回時的**同一個**格式檢查函式；不合格的那一條整份退回（和其他草稿檢查一樣）。
- 採用時直接寫進 `own_conditions`：`origin = AI_DRAFT_ACCEPTED`、有 `accepted_at`、狀態照 `acceptStatus`。**不再送改寫、不再到持股頁確認**。
- 他之後在編輯論點頁**親手改**出場條件的字 → 照舊走改寫與確認（那是意圖）。

### 2.3 同業（X2）

- 草稿的同業（`sources.peers`）採用時直接存進 `webSources.peers`。程式先核對 EDGAR 代號存在（`company_tickers` 對得到 CIK）；對不到的那一家不存，存檔結果寫一行原因。
- 草稿不再提出網域（`sources.domains` 拿掉；`own_draft_v3` 的輸出格式少這一欄）。

### 2.4 防線的前後對照（取代 `web_evidence` §2.4 第 1 點）

第 1 點「每一條都要使用者勾選才生效」拿掉，原本它擋的「寫前提的 AI 把題目出得容易過」改由下面這些擋（都已經有，第 3 點是新的）：

| 擋法 | 在哪裡 |
|---|---|
| 程式檢查：至少 2 條不是信念、查得到的要寫正面的「怎樣算證實」、`breaks_if` 不能一開始就成立、本文不能放會過時的數字、至少一條財報門檻的出場條件 | `ownDraft.ts`（T60） |

## 3. AI 建議的條件：自動監測，成立時重新審查（X5；改 `own_thesis` §1.5「從建議到監測中」）

- 審查建議的條件（`payload.proposed_conditions`，三票一致才寫入，照舊）寫入時，狀態直接照 `acceptStatus` 變成 `ACTIVE`／`REVIEW_ONLY`／`MANUAL`，`origin = 'AI'`，**`action = 'REVIEW'`**（重新審查），`accepted_at` 留空（代表不是使用者定的）。
- 成立時：照現有的「重新審查」條件處理（`condReviewDue`，開一次審查，觸發原因 `CONDITION`），**不發甲類通知、不會叫你賣**。要不要賣由那次審查照 §1.9 判。
- `tier_if_met`（AI 建議成立時的檔位）照舊存，顯示成「AI 建議成立時減半；目前設定是重新審查」。
- **使用者可以改動作**（持股頁的「改成立時的動作」）：改成出清或減半 → 這條變成「你定的」（寫 `accepted_at`），之後的審查換不掉；這是意圖，所以留。
- **之後的審查怎麼換**：AI 定、使用者沒動過的條件，算在「AI 監測中」，每檔最多 3 條。下一次三票一致的審查有寫入新建議時，還沒成立的舊 AI 條件標 `EXPIRED`（和現在的 `PROPOSED` 一樣）；沒提時留著。已經成立的（`MET`）不動。
- 上限：「你定的」照舊 8 條；「AI 監測中」另算 3 條。
- `PROPOSED` 狀態不再產生（舊資料照舊顯示）。「要看的事」的 `PROPOSED_CONDS` 拿掉。
- 持股頁條件區分兩組：「你定的」「AI 監測中（成立時重新審查）」。

## 4. 新風險不列「要看的事」（X6；改 `composite_layer_design` §3）

- `NEW_RISK` 不再列進「要看的事」，「看過了，不加」的按鈕拿掉（`/api/ops/own-risk` 留著不用，舊的 `riskSeen` 照舊讀）。
- 新風險照舊顯示在審查紀錄頁與持股頁的審查摘要裡。
- **帶進下一份草稿**：草稿的證據包多一份文件「最近 180 天審查的新眼光提出的風險」（每件的一句與引用的原文片段；最多 6 件，新的在前）。草稿的反方要看它。**審查的證據包不放**（新眼光是刻意不看前提的角色，審查也不需要；判的人看不到出題的過程照舊）。
- **同一件反覆出現**：兩次不同的審查的新風險引用了**同一份文件的同一段原文**（`source_id` 與 `quote` 相同），算同一件反覆出現 → 這檔自動開一次草稿（§5 的觸發 `RISK_REPEAT`）。只比對原文，不同文件講同一件事認不出來（寫明的限制）。

## 5. 自動草擬的時機（X8；改 `web_evidence` §2.5）

下面這些情況，**當天的每日流程自動開一次草稿**（原本只在「要看的事」放連結）：

| 觸發 | 原本 |
|---|---|
| `PREMISE_NO_DATA`：你的前提最近一次審查 3 票都是證據不足 | 連結 |
| `PREMISE_UNVERIFIED`：同一條前提連續 3 次審查沒驗到 | 連結 |
| `NO_CONSENSUS`：最近幾次審查都沒有一致結論 | 連結 |
| `HALF_NO_EXIT`：減半中而沒有出場條件 | 只提醒 |
| `THESIS_OLD`：論點滿一年 | 連結 |
| `RISK_REPEAT`：同一件新風險出現兩次（§4） | 新的 |
| `NO_THESIS`：只有系統預設前提（新自選的那一次自動草擬沒有跑成，或那時還沒有這個功能） | 只提醒 |

- **不自動開的**：這檔有還沒回覆的乙類通知，或最近 30 個日曆天內有前提被判不成立（§2.4 第 6 點的防線照舊；使用者自己按照舊可以）。
- **頻率**：同一個觸發（`要看的事` 的 key）只自動開一次；每檔 7 個日曆天最多 1 次（照舊，自動與手動共用）；同一天最多自動開 2 檔（控制雲端次數，其餘排到隔天）。
- 草稿好了：照舊列 `DRAFT_READY`；自動開的不推 LINE（照舊）。使用者決定採不採用（§2）。
- 「要看的事」那一行改寫成「已經請 stock bot 草擬（M/D），好了會列在這裡」，不再要他去按。
- 這不是「定期重寫」（第 5 點）：只在事件發生時開，而且草稿不採用就不生效。

## 6. 「這次不做」的理由：一鍵選（保留但變輕）

- 要寫理由的地方（甲類「這次不做」、乙類「不同意，不動」、慢規則減半與崩盤項目的「這次不做」）多一排選項，點一下就填好：
  - 甲類、慢規則、崩盤：「價格已經反映」「想再觀察一陣子」「這檔對我有其他用途（避險、配置）」「其他」
  - 乙類：「我認為這條前提還成立」「報導不可信」「想等下一份財報」「其他」
- 選「其他」才要自己打字；其他選項的文字就是理由（照舊存進論點檔、進下一次審查、乙類的「不同意」照舊進靜默期）。
- 理由長度與檢查照舊（`missingReasons`）。

## 9. 不做的與理由

- **讓分析師自己評級**：自己出題自己改考卷（§1.1 第 2 點）。
- **評級時讀網頁內文**：會被網頁的自我宣稱或夾帶的指示影響（§1.1 第 3 點）。
- **定期重評**：級別會漂；種子是覆寫的方法。
- **`LEAD` 的網頁也能判前提**：內容農場、互相轉貼會讓「兩個網域都這樣說」失真。
- **自動採用草稿**：論點是「你為什麼持有」，採用仍然要他按一下（意圖）。
- **AI 建議的條件成立時直接叫你賣**：沒有人點過頭的條件只開審查，賣不賣由審查照 §1.9 判。
