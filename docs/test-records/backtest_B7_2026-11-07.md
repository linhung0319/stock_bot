# B-7 依緊急程度分級通知

> 日期：2026-11-07
> 對應：`design_v2_momentum_2026-11-07.md` §2.5（觸發與通知）
> 腳本：`backtest/account_backtest.py` 的 `run_b7`，執行 `uv run python backtest/account_backtest.py`（依序跑 B-5、B-6、B-7）
> 原始輸出：`backtest/results/B7_summary.md`、`B7_account.csv`、`B7_orders_<年>.csv`（門檻 5% 版本的每一次下單，附原因）

---

## 1. 問題

「觸發」（系統的目標分配變了）和「通知」（叫使用者操作）可以分開。B-5 只比較了兩個極端：自選訊號全部隔天執行，或全部等到月報。B-7 測中間的做法：**單筆變動夠大的自選訊號當天通知、隔天執行，其餘累積到月報。**

## 2. 結論

1. **門檻 5% 時，月中的當天通知每年只有 0.3～0.6 次**（約兩到三年一次），報酬和「全部併入月報」相同（13.7% vs 13.8%；20.7% vs 20.4%，差異在雜訊範圍內）。
2. **門檻越低，月中通知越多，報酬沒有變好。** 門檻 3%：每年 1.5～4.7 次；門檻 2%：約 5 次，已接近「全部隔天執行」（每年 13 個下單日）。
3. **執行快慢不影響報酬**：從「全部月報」到「全部隔天執行」，年化都在 13.7～13.8% 和 19.8～20.7% 之間，沒有一致的方向。慢規則本來就慢，晚幾週執行沒有代價。所以門檻要依使用者能接受多少次月中通知、以及多大的部位不想等來決定，不是報酬。
4. **5% 抓到的正是「部位已經變大的股票」。** 標準比重 5% 的股票減半只變動 2.5%，不會觸發當天通知；會觸發的是漲到 10% 以上的股票，例如 NVDA 在 2018-10、2024-07 減半（各 6.2%）、MSFT 在 2020-03 減半（6.3%）。部位越大，越不該等。
5. **建議採用門檻 5%**，作為新的主要方案。

## 3. 方法

| 項目 | 設定 |
|---|---|
| 比例 | 自選 20%、動能 30%、核心 50%（使用者 2026-11-07 決定） |
| 其他規則 | 單檔上限 15%→10%、跨桶上限 15%→10%、搭便車、崩盤規則減一半、依波動度減碼 |
| 緊急的定義 | 自選慢規則的一次減半或加回，變動金額 ≥ 總資產的門檻 → 隔天開盤執行；其餘等下一次月報 |
| 門檻 | 10%、5%、3%、2%；對照「全部併入月報」與「全部隔天執行」 |
| 沒有模擬 | 任務 A 的硬事件（無法回測）；入金出金（B-6 已測） |

## 5. 限制

- 自選股是事後贏家；2015 年以前的動能部位有倖存者偏差。
- 「緊急」只用金額定義。任務 A 的硬事件（造假、收購、重大監管）也屬於緊急，但無法回測。
- 門檻比的是總資產；自選股標準比重改變（例如依波動度分配）會改變觸發次數。
