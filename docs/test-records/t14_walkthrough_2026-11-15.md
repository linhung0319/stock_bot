## 開始前發現的問題（查帳戶狀態與程式時發現）

### 問題 1：四檔自選的標準比重都是空的（已修，0.9.1）

- **現象**：帳戶頁每檔自選都顯示「標準比重 —」；D1 的 `rule.own.*.stdWeight` 全是 `null`。
- **原因**：建立帳戶時，標準比重留空就用推薦值（依 126 天波動度反比）。其中一檔上市不到 126 天，波動度算出 NaN，正規化時整組都變成 NaN，存進 JSON 變成 `null`。
- **後果**：`null` 參與計算時當成 0——慢規則的「加回」買不到東西（帳上有一檔已經在數加回的天數）、入金不會分給自選、F24 的「回到標準」是 0 股。T17 重建帳戶時同一檔還在，會再發生。
- **修正**（使用者選定，設計 §10 第 37 點）：波動度用能拿到的天數（最多 126、至少 20）；不到 20 天用其他自選的平均波動度；全部算不出來就平分。測試：`test/t14-fixes.test.ts`「推薦標準比重」4 個。
- **測試資料修補**：部署 0.9.1 後，用同一個函式、正式環境存的收盤價（2026-11-13）算出四檔的標準比重，在 D1 補上（`account_state` rev 3 → 4，`account_history` 第 4 版的 cause 寫明）。正式網站帳戶頁確認四檔都有標準比重，合計等於自選預算。

### 問題 2：緊急賣沒有理由欄；自選賣光後還留在自選（已修，0.9.1）

- **現況**：網站沒有專門的「緊急賣」入口。做法是到券商賣掉，回來填快照。
  - 自選、動能：快照出現「清單外的變動」，跳出分類通知問屬於哪一桶。賣出這一側**沒有理由欄**（API 收得到，畫面沒給）；按鈕永遠是「歸自選」，即使自選沒有這檔。
  - 核心（VOO／SGOV）：直接歸核心，不問，**沒有地方寫理由**。
  - 自選整檔賣光後，這檔仍留在自選、0 股，之後加回或入金會把它買回來。
- **修正**（使用者選定，不另做入口；設計 §10 第 37 點）：
  - 快照頁多一欄「這次自己交易的原因（選填）」，記在清單外變動的事件上（核心也記），並帶進分類通知的理由欄。
  - 賣出的分類有「為什麼賣（選填）」，記在事件與「沒照規則做的」紀錄上。按鈕照實際持有顯示「從自選扣」「從動能扣」。
  - 自選賣到 0 股時，多一個預設勾選的「同時移出自選」：和移除自選相同，之後不再追蹤、不會被買回；影子記「如果繼續持有」。
- **測試**：`test/t14-fixes.test.ts`「緊急賣」3 個（核心的原因、自選賣一半的原因與不能移出、賣光移出／不勾留著／動能不能用）；`test/site.test.ts`「緊急賣（T14）」1 個（經網站 API：快照原因帶進分類、移出自選、核心原因、只賣一部分不能移出、原因太長擋下）。

### 問題 3：動能桶是空的，沒有東西可以緊急賣（測試資料修補）

- 動能要等 12/1 的月報才第一次買；「清單外買進歸動能」也要那檔在當月動能名單上，名單是空的。
- 使用者選定：在測試帳戶的動能名單補上本月排名第 2 的那檔（只改測試資料，和問題 1 同一次修補，rev 4）。情境 3 先在快照買進、分類到動能（順便測這條路），再賣掉。
- 留意：12/1 的月報會把這檔當成已持有的動能名單。T17 會清掉帳戶，不影響上線。

## 情境 1～3 第一次走（0.9.1，正式網站，2026-11-15）

- **情境 1（核心賣 2 股）**：使用者回報沒問題。D1：核心那一檔少了 2 股、記成「核心的手動交易」，沒有產生任何通知（照預期）。**事件上沒有使用者寫的原因**：可能沒填，也可能瀏覽器還是舊版頁面；快照頁之後重做，沒有再追。
- **情境 2（自選整檔賣光）**：完全照預期。分類通知帶入快照寫的原因、預設勾選移出自選；分類後這檔不在自選、事件與影子紀錄都在（「手動交易：賣光並移出自選（如果繼續持有）」）。使用者回饋：見問題 4。
- **情境 3（動能）**：D1 顯示「買進 10 股」那則分類一直沒有回答（沒有按「歸動能」）；之後同一檔又 −10、+10，產生 3 則「現金和預期差」的問題卡在待辦，帳上留下 10 股未分類。使用者回饋：分類畫面讓人以為會當成自選加進去，而且現金一定對不上。見問題 4、5。

### 問題 4：分類通知多一步、理由要填兩次（已改，0.10.0）

- 使用者：快照已經有地方寫理由，「去回答」又要再填一次；既然會勾「移出自選」，賣到 0 就直接移出。清單外買進時不知道會被放哪一桶，快照的新增應該也分自選、動能、核心。
- **改法**（使用者提出並選定，設計 §10 第 38 點）：快照照帳戶的三桶分開填，變動放哪一桶由使用者決定，不再產生分類通知；自選股數改成 0 就移出自選；自選加新代號就是新增自選（可寫為什麼買）。新增／移除自選兩頁拿掉，標準比重、前提、AI 草擬前提改在持股頁。動能的清單外買進照舊限制（使用者選定）。

### 問題 5：現金一定對不上，卻一直被問（已改，0.10.0）

- 使用者：網站的股價不一定最新、也不是實際成交價，結果的現金一定有差；快照就是直接寫結果，入金出金由另外的操作表示。
- **改法**（使用者選定）：差額不問，記成「其他現金變動」（算報酬）；超過總資產 2% 時結果頁提醒去登記入金／出金，不擋路。

### 測試資料整理（0.10.0 部署後）

- 情境 3 卡住的 3 則「現金和預期差」由 Claude 用管理端點回答「其他」清掉（測試資料）。那則沒回答的分類通知和 10 股未分類留著，下一次分桶快照放進某一桶時會一起結束（順便測改版前的舊資料怎麼收尾）。

### 問題 4、5 的測試

- `test/t14-fixes.test.ts`「分桶快照」7 個：核心賣出與原因；自選賣光自動移出、賣一部分留著、成交價差記成其他現金變動；自選加新代號（推薦標準比重、為什麼買成為前提、沒寫用預設）；動能清單外買進的限制與核心／自選的代號檢查（擋下時帳戶不變）；同一檔兩桶都有時只賣動能；清單照桶對帳（照做完成、少做問補做、策略單欠單、沒按回覆但已照做、移除自選清單照做不算自己賣光）；改版前的未分類持股（放進桶、分類通知結束、月報不再暫停、不重複扣現金）。「持股頁」1 個（改標準比重、加前提取代系統預設）。

## 情境 1～3 第二次走（0.10.0，正式網站，2026-11-15）

- **R1（核心賣 2 股）**：照預期記成「核心的手動交易」，沒有任何通知。事件上又沒有原因（R3 有），原因欄可能不顯眼，0.11.0 移到右側送出快照那一欄。
- **R2（舊的未分類持股放動能）**：使用者是用待辦裡那則舊分類通知按「歸動能」完成，不是用新快照；結果正確（動能 +10、舊通知結束）。新快照收尾舊資料的路徑只有自動測試驗證過。
- **R3（動能賣光、現金故意少 5 元）**：照預期。動能清空、事件帶原因、結果頁與帳本都有「其他現金變動 −5」。
- **R4（自選賣到 0）**：照預期自動移出自選，影子紀錄「賣光並移出自選（如果繼續持有）」。
- 持股頁看得到標準比重與慢規則狀態（使用者確認）。
- 第一次走時 Claude 回答「其他」清掉的 3 則現金問題，帳本留下三行 ±5,341 的其他現金變動，淨 +5,341 被算成報酬（測試資料，T17 清掉）。

### 問題 6：快照頁的版面（已改，0.11.0）

- 使用者：快照頁要像帳戶一樣三桶有各自的顏色；現金歸核心、在那裡顯示帳上的現金，使用者直接填買賣後的現金——快照就是填帳戶現在的狀態；理由放到右側送出快照那邊；核心有短債與現金，帳戶頁也要有短債。
- 改法：照做（設計 §10 第 38 點最後一項）。測試：`test/site.test.ts`「復原上一份快照」裡檢查帳戶頁核心固定是 VOO、SGOV、現金三列。版面只在本機看過（headless Edge，桌面 1400px、手機 390px，沒有 console 錯誤；送出後結果頁有其他現金變動與復原按鈕）。

### 問題 7：送出快照後想改（已改，0.11.0）

- 使用者：填了股數忘了改現金，看到差額時想回去改，不確定有沒有這個功能。原本只能再填一次；自選不小心填 0 會被移出自選，再填回來前提與狀態都不見。
- 改法（使用者選定，設計 §10 第 39 點）：最後一份快照可以復原，帳戶完整回到送出前；之後有每日流程或其他操作就不能復原。
- 測試：`test/site.test.ts`「復原上一份快照（T14）」（真實帳本：入金清單＋清單外賣出＋現金差，復原後帳戶狀態、通知、帳本事件數、影子數、快照數都回到送出前，history 有「復原快照」，不能復原第二次；重填後做了別的操作就不能復原）、「示範模式也可以復原上一份快照」（不小心把自選填 0，復原後前提與規則狀態都回來）；`test/records.test.ts` 不匯出的表多 `snapshot_undo`。本機 headless Edge 從待辦頁按「復原這份快照」，帳戶回到送出前並跳到填快照頁。
