## 執行中做的決定

### T60（前提的新欄位）

- 舊資料：`breaksIf` 型別是 `string[] | string`，舊的一段字讀時當成一句；新增自選的舊入口照舊寫一段字。沒有 `verify` 的前提（手寫沒填、舊的）照舊進審查。
- 信念不進審查的做法：直接從審查、減半檢視、硬事件、條件確認的證據包拿掉（prompt 不用改）；草稿與出場條件的改寫照樣帶（才能沿用、對得到前提）。`externalNeeds`、`PREMISE_NO_DATA` 也排除信念。
- 審查的證據包現在帶 `breaksIf` 陣列、`confirmsIf`、`verify`（使用者同意過的前提欄位，不算草稿的出題過程，不違反 `web_evidence` §2.4 第 4 點）；`own_review_v3`、`own_drop_v3` 還沒說明這幾欄，T61 升版。
- 「沒驗到」怎麼算：不是三票一致成立、也不是三票一致不成立就算一次（證據不足、票數不一致都算）；這條沒有票的審查（逾時、減半檢視、當時是信念）不算也不中斷；前提的字改過之前的不算（只改標點不算改）。「要看的事」每 6 個月再列一次、同一條不再列 `PREMISE_NO_DATA`。`unverifiedStreak()` 另回傳最近一次證實的日期，給 T61 的四種寫法。
- 只改三個欄位（含改標成信念）不算論點變動，隔天不開審查（和 T56 對 `breaksIf` 的規則一致）。
- 網站手寫不強制「至少 2 條不是信念」（設計只說草稿退回）；預覽少於 2 條查得到時用黃字提醒。
- 草稿檢查 1（子句已在財報成立）只認幾種中文寫法：一句一個指標、低於／高於數字、季減、年減、轉負，期間「連兩季」「任一季」或沒寫；只比 `verify.by` 是 XBRL 或 FILING 的前提。往後看的寫法、主詞是別的、一句兩個指標都不擋（交給 prompt）。
- 檢查 2 擋的字樣：最新一季、最近一季、本季、這一季、財測約、財測為、目前股價、現在股價、目前的股價、現價；不擋「上一季」（相對比較是合理寫法）。
- 部署時還在跑的 v1 草稿會用 v2 規則檢查而失敗；失敗的不算 7 天一次，可以再按。已存的 v1 草稿照樣顯示、能勾。
- 多句的 `breaksIf` 意思是「任一句成立就算」；T61 的審查 prompt 照同一個意思。
- 討論包、收尾區塊與 `/thesis` 不帶新欄位：從那條路存檔時新欄位照舊不變，但不能在那裡標信念。
