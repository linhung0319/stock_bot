# 實作計畫（2026-11-11）

> 依據：`docs/design/design_v2_momentum_2026-11-07.md`（架構與規則的唯一依據，系統架構在 §2.7）、`docs/design/ai_layer_design_2026-11-08.md`（AI 功能卡片；最上面的「2026-11-11 更新」優先於卡片內文）。
> 用法：依序做。每完成一個任務，把該任務的 `[ ]` 改成 `[x]`，並在「進度紀錄」（`docs/plan/progress_log.md`）加一行。新的工作階段從第一個未完成的任務接著做。

## 工作規則

1. **不改已決定的設計。** 發現規格沒寫到的地方：提出建議做法、照建議做、寫進設計文件 §10，並在進度紀錄註明。要推翻已決定的事項才停下來問。
2. **需要使用者本人的事才停下來**：登入帳號、建立金鑰、花錢、把個人資料（例如 email）送到外部服務。停下來前，先把不需要這些的部分做完，並把使用者要做的步驟一次列清楚。
3. **金鑰**只用 `wrangler secret` 或雲端環境設定，不寫進 repo、不印在輸出。LINE token 只放 Cloudflare。不儲存券商帳密，系統不下單。
4. **規則引擎是純函式**：不讀網路、不讀時鐘、不碰儲存。輸入資料與日期，輸出狀態與清單。這樣才能用歷史資料重放驗收。
5. **每個任務都要有測試，測試通過才算完成。** 回報時照實寫：哪些通過、哪些沒做、哪些只在本機驗證過。
6. Python 一律用 `uv run`。`backtest/` 與 `backtest/results/` 是凍結的依據，不修改（T2 需要匯出資料時另外寫腳本）。
7. 介面文字用繁體中文；程式識別字用英文。
8. 只做任務寫到的範圍。原型（`prototype/`）沒做的功能（換 strategy、劃撥、股利、零股）除非任務有寫，否則不做。

## 技術預設（可依實測調整，調整時寫進進度紀錄）

- 新程式放在 `worker/`：TypeScript、Cloudflare Workers、D1（帳本與紀錄）、R2 或 KV（價格與快照）、Vitest。
- `worker/src/engine/`：規則引擎（純函式）。`worker/src/data/`：資料抓取。`worker/src/app/`：排程、網站、LINE、AI 任務端點。
- 網站由同一個 Worker 提供，畫面以 `prototype/` 為參考；用 Cloudflare Access 限制登入。
- AI 的 prompt 與子代理定義放 `ai/`（雲端排程會 clone 這個 repo）。

## 階段一：規則引擎（不需要任何帳號）

### [x] T0 專案骨架
- 建立 `worker/`（TypeScript、Vitest、wrangler 設定、lint）。本機 `npm test` 能跑。
- 完成條件：空專案測試通過；`README` 寫明怎麼跑測試與本機開發。

### [x] T1 引擎核心
照設計文件實作，Python 的 `backtest/account_backtest.py`、`backtest/momentum_backtest.py` 是對照用的參考實作。
- 指標：均線、52 週高點跌幅、252 日報酬、波動度。
- 自選慢規則（§2.2）：減半＝賣掉當時股數的一半；加回條件；新增自選的初始狀態；R1 只記錄。
- 動能（§3）：市值前 50 的股票池、前 5 名進場、掉出前 15 名出場、lazy 交易。
- 依波動度減碼（§4.1），含 0.10 遲滯。
- 崩盤規則（§4.4）。
- 上限：單檔 15%→10%、跨桶 10%／15%（§2.2）。
- 三桶 20／30／50、核心當清算中心、比例調整只搭便車（§2.1）。
- 合併下單、觸發與通知分級（單筆 ≥ 總資產 5% 當天，其餘併入月報，§2.5）。
- 完成條件：每條規則有單元測試，案例取自設計文件的數字與例子。

### [x] T2 重放驗收
- 另寫一支 Python 腳本，把回測用的輸入（每日價格、每月股票池與排名所需資料）匯出成固定檔。資料來源見 `backtest/momentum_backtest.py`（另一個專案的 LEAN 資料夾，唯讀）。
- 在 Node 用 T1 的引擎以「比重模式」（不取整股、成本 5 bp）重放 2000–2026 與 2013–2026，對照 `backtest/results/B8_account.csv` 的「緩衝 0.10」情境與 `B8_orders_*.csv`。先確認 `B8_orders_*.csv` 是哪個情境的輸出（看 `run_b8`）。
- 完成條件：下單日與每筆方向一致；年化、Sharpe、最大回撤與回測相差在四捨五入範圍內。對不上的地方逐一查明原因並寫下來，不調整容許範圍來讓它通過。

### [x] T3 帳本與使用者操作
- 快照式帳本（§2.1.1）：兩份快照相減拆成事件、分到各桶；每桶單位淨值；清單以整股為單位，用前一日收盤價換算。
- 入金、出金（含出金順序與單檔上限預先檢查）、改比例、新增／移除自選、轉入自選、認養、排除（§2.1.1、§2.3）。
- 操作和清單不同時的處理（§2.3.1），含 2026-11-11 定案的原型假設（設計 §10 第 25 點）。
- 完成條件：`prototype/README.md` 的 7 個情境各寫成一個固定測試，照定案後的規則（不是照原型程式的舊行為）。

## 階段二：兩項會影響架構的實測（需要使用者的帳號）

### [x] T4 從 Worker 抓資料
- 部署一個測試 Worker，從 Cloudflare 抓：Yahoo 日線（約 60 檔）、SSGA 的 SPY 每日持股檔、Wikipedia 的 S&P 500 名單、EDGAR `submissions`。連續幾天各跑一次，記錄成功率與耗時。
- EDGAR 要求 User-Agent 帶聯絡方式：先問使用者要用什麼。
- 需要使用者：Cloudflare 帳號、`wrangler login`。
- 完成條件：寫下每個來源可不可用。Yahoo 不穩時提出替代做法（例如改由別處抓好再寫入儲存），照建議調整 T6。

### [ ] T5 Worker 與雲端排程來回一次
- Worker 提供兩個端點：取證據包、送回結果（驗證 header、只限該任務編號）。
- 建一個測試用的雲端排程：由 Worker 以 API 觸發，取回一份假的證據包，送回固定格式的 JSON。
- 一併量測或確認：無人值守時對外請求會不會被擋、從觸發到收到結果要多久、子代理能不能指定 Haiku、network secret 的設定方式。
- 動手前先讀目前的官方文件（`code.claude.com/docs/en/routines.md`、`cloud-environments.md`）；這個功能是研究預覽，限制可能已經變了。
- 需要使用者：在 claude.ai 建立雲端環境（允許網域、network secret）與排程任務、產生觸發用的 token。
- 完成條件：寫下結果。送回結果被擋時，改用 git push 傳結果，並更新設計 §2.7。

## 階段三：不含 AI 的可用系統

### [x] T6 資料層與儲存
- D1 結構：快照、事件、各桶持股與規則狀態、通知與回覆、成分股快照、AI 紀錄。
- 每日抓價格與成分股並存檔；SPY 持股檔和 Wikipedia 不一致時暫停換股並通知。
- 資料新鮮度：最新 K 線不是上一個美股交易日（要有交易日曆）就不產生訊號並告警。
- 完成條件：本機與測試環境都能連跑數日；缺資料、舊資料、來源不一致各有測試。

### [x] T7 每日與每月流程、LINE、缺席告警
- Worker cron：每天收盤後檢查；每月第一個交易日開盤前出月報。以美東時間與交易日曆判斷。
- LINE 推播：每則附清單（股數）與網站連結；當天通知與月報兩級。
- 缺席告警：流程沒跑完、資料沒更新、AI 任務逾時。
- 紙上交易模式：流程全跑，帳本標記為紙上。
- 需要使用者：建立 LINE Messaging API channel，用 `wrangler secret` 放 token。
- 完成條件：在測試環境實際收到一則月報與一則告警。

### [x] T8 網站
- 輸入：填快照、回覆清單（照規則／照 AI／部分完成／這次不做）、入金出金、改比例、新增／移除自選、排除、轉入自選。
- 顯示：帳戶三桶、每檔屬於哪一桶與規則狀態、通知紀錄、每一項「為什麼」。
- Cloudflare Access 限制登入。
- 需要使用者：設定 Access（誰能登入）。
- 完成條件：用網站走完情境 ① 與 ⑤（平常的月報、自己的操作），結果和 T3 的測試一致。

**到這裡可以開始紙上交易。**
