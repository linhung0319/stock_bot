# stock bot 原型（2026-11-09）

用來**操作看看**目前的設計：隨著時間、事件與你的操作，背後的規則與 AI 層會做什麼。不是實作，也不連任何外部服務。

- **怎麼開**：直接雙擊 `index.html`（不需要伺服器，也不用安裝任何東西）。
- **資料**：價格、新聞、申報、AI 輸出全部是假的。崩盤規則的基準率表（2000–2026 的 17 次）是 `ai_layer_design_2026-11-08.md` §3.3 的真實數字。
- **依據**：`design_v2_momentum_2026-11-07.md`（§2.0 觸發總表 F1–F25 是主要對照）、`ai_layer_design_2026-11-08.md`（功能卡片）。

## 畫面

| 區塊 | 內容 |
|---|---|
| 上：現在 | 情境的時間軸（每個點是一則通知，紅圈＝等你回覆，黑線＝現在）、「剛才」你按了什麼、發生了什麼、「接下來」該做什麼，右邊的大按鈕就是接下來該按的 |
| 左：LINE 通知 | 你在手機上看到的：每則通知附清單（股數），規則與 AI 並列時可以選；每一項可展開「為什麼有這一項」；處理完後氣泡底下列出「這則通知之後」發生的事。下方是你自己會做的操作（入金、出金、改比例、新增／移除自選、手動交易） |
| 中：時間軸 | 以「回合」為單位（你每按一次按鈕＝一個圓點：前進時間、回覆、自己的操作），底下列出那一步發生的事：規則判斷、AI 呼叫、權限等級（A0–A4）、通知等級、哪一則通知；例行檢查預設收起來；回合結尾列出產生的通知與帳本變動 |
| 中：網站 | AI 報告（前提逐條、條件、證據、輸出外殼 JSON、匯出給 AI 的 md）、影子組合、崩盤規則保險紀錄、個股時間軸、排除／否決清單、⚠ 規格未定 |
| 中：觸發總表 | F1–F25，以及這次操作中各功能被觸發幾次（點日期跳到那條紀錄） |
| 中：疑問筆記 | 操作時記下「和我想的不一樣」的地方，匯出成 md |
| 右：帳戶 | 三桶占比與預算、每一股屬於哪一桶（上一回合有變動的列用綠底＋變動欄標出）、自選慢規則狀態、動能排名、走勢圖（收盤、200 日均線、減半線、這檔的通知日） |

時間模型：每個交易日分「開盤前（台灣早上）」與「收盤後」。月報在每月第一個交易日開盤前；當天通知在收盤後發、隔天開盤執行。回覆後的下一個開盤以開盤價成交，原型自動模擬你填快照，並把快照差異拆成事件分到各桶。

## 原型自己做的假設（設計文件沒寫清楚的地方）

碰到時會在「背後發生什麼」標 ⚠，並集中在「網站 → ⚠ 規格未定」。目前有：

1. 慢規則「減半」＝賣掉目前股數的一半；AI 檔位「標準的一半」＝標準比重 × 0.5。部位高於標準時兩者不同；原型在 F7 把 AI 的 HALF 當成同意規則。
2. F8 加回時，最近一次 F24 是「不動」：當成 AI 沒有異議（另一種解讀「不動＝維持減半」會讓每次加回都多一行）。
3. 照 AI「出清」＝移出自選（等同 F15），之後不再加回。
4. 照 AI 選「標準的一半／回到標準」會改變慢規則狀態。
5. 任務 A 否決要 3 票一致；F19 硬事件通知預設「不做」。
6. F25「每檔每月 1 則」只算 F25，不含同月的 F7 通知。
7. 改自選比例時，自選股數與標準比重等比例縮放。
8. 認養的那一筆照常買進、記在自選；動能那一格下個月才遞補。
9. 手動買進後歸到動能桶、但不在動能名單 → 下個月當成「上次沒照做的出場」。
10. 「補做差額」還沒做、月報又重列同一檔時，以月報為準。
11. 入金遇到月報日沒有合併成一份清單（設計說要合併）。

**2026-11-11 定案**（寫在 `design_v2_momentum_2026-11-07.md` §10 第 25 點；原型程式沒有跟著改）：

- 假設 1：全系統只有一種「減半」＝賣掉當時持有股數的一半；AI 檔位「標準的一半」改稱「減半」，和規則是同一個動作。
- 假設 3、4：照原型的做法。
- 假設 9：改掉。清單外買進的股票只能歸自選，除非該檔在當月動能清單上且還沒買足。
- 假設 11：要合併。月報還沒回覆就登記入金 → 重算並取代月報清單；已回覆 → 另給入金清單。
- 假設 2、5、6、7、8、10：照原型的做法。
