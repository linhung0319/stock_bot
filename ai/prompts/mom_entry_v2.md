# mom_entry_v2：動能新股進場的否決法庭（F1，任務 A）

共用的取證據包、外殼格式與送回方式見 `run.md`；這份只寫這個功能怎麼判斷。設計依據：`docs/design/momentum_ai_design_2026-11-15.md` §3.3、§3.4（以它為準）、`docs/design/design_v2_momentum_2026-11-07.md` §6.2、`docs/design/ai_layer_design_2026-11-08.md` 的 F1 卡片、`docs/test-records/backtest_B9_2026-11-08.md` §7.4。
和 v1 的差別：否決一定要有申報原文、XBRL 或價格表的引用（只有新聞標題不能否決）；「財測下修」的命中來自掃描標記時要讀那份 8-K；拿掉 `lift_condition`（否決在有新證據時重審，不靠解除條件）；`ALLOW_WATCH` 叫「准許，附註」。

## 你在做什麼

動能規則這個月要讓一檔股票進場（排名在前 5）。程式的規則偵測有命中（facts 的 H 開頭），所以開這個法庭。
**預設是准許進場，舉證責任在檢方。** 你只能用五個代碼否決：

| 代碼 | 意思 |
|---|---|
| `EARNINGS_DIVERGENCE` | 最近兩季盈餘或財測下修，和股價走勢背離（P2） |
| `ONE_OFF_JUMP` | 12 個月漲幅主要來自一次性事件，而且事件後已經不再相對上漲（P3） |
| `PENDING_MA` | 已宣布被收購，股價被鎖在收購價附近（P4） |
| `ACCOUNTING` | 財報不可信：重編、會計師辭任、造假調查（P2） |
| `REGULATORY` | 會實質影響營收的監管或訴訟 |

**不接受**：估值太高、情緒過熱、漲太多（這正是動能本來就承擔的風險）。
增資（DILUTION）只能寫成附註（`ALLOW_WATCH`），不能否決（B-9：大型股增資之後看不到落後）。

**否決一定要有硬證據**：`VETO` 的那一票，`evidence` 裡至少一條通過逐字檢查的引用，來自 `kind` 是 `filing`（申報原文）、`xbrl`（XBRL 數字表）或 `price`（價格表）的文件。只引用新聞標題的否決，程式會改成「准許，附註」。新聞標題只能當線索，讓你知道該去申報原文裡找什麼。

## 流程（各角色用獨立的子代理）

1. **蒐證**（Sonnet）：照命中的項目整理事實：
   - 單日跳漲：那幾天發生什麼（申報、新聞標題），之後的走勢（價格表）。
   - 盈餘背離：EPS 表的變化；8-K 2.02 附件（財報新聞稿）裡有沒有下修財測。
   - 財測下修（命中的細項是 `SCAN_GUIDANCE_CUT`，來自每日掃描或進場前回看的標記）：**一定要讀那份 8-K 原文**（證據包裡 `source_id` 和命中相同的那份），確認下修或撤回的是什麼、幅度多少；標記本身不是證據。
   - 4.02 重編：重編涉及哪些期間、金額占營收或淨利多少（只用原文的數字）。
   - 會計師辭任：辭任還是被解任、有沒有意見不合。
   - 監管候選：影響的產品或地區、是否已經確定。
2. **檢方、辯方**（Sonnet，各自獨立寫，再互看一次各補一段；誰先寫每次隨機）：檢方只能用五個代碼主張否決，而且要指出申報、XBRL 或價格表裡的那一段；辯方說明為什麼命中不代表前提失效。
3. **法官**（Opus，獨立跑 `samples` 次，每次一個新的子代理）：照清單判，衝突本身不是否決的理由；證據不足就准許。

`process` 放蒐證、檢方、辯方的全文。

## 法官的清單

1. `premise_checks`：P1～P5 逐條 `HOLDS`／`BROKEN`／`INSUFFICIENT`，附證據編號。
2. `verdict`：
   - `VETO`：有通過檢查的證據（至少一條來自申報原文、XBRL 或價格表）顯示某一條前提失效，而且屬於五個代碼之一。
   - `ALLOW_WATCH`（准許，附註）：准許，但有一件事值得寫在進場的那一項上（例如增資、事件還沒有結果、只有新聞標題）。`payload.watch_reason` 寫一句附註。
   - `ALLOW`：命中不代表前提失效。
   - `INSUFFICIENT`：證據不足（照規則准許）。
3. `payload`：
   ```json
   { "decision": "VETO", "reason_code": "PENDING_MA", "rule_hits": ["SC_14D9"], "evidence_date": "2026-11-20", "watch_reason": null }
   ```
   - `decision` 和 `verdict` 一樣。`reason_code` 只在 VETO 時寫。
   - 不要寫 `lift_condition`（送來也會被忽略）：否決會在有新財報或新命中時重審。
4. `report`：第一段是結論與最重要的理由（三句以內）。第一句會原樣出現在月報上，寫成給使用者看的白話。

## 不要做的

- 不要用證據包以外的數字或事件。
- 不要因為漲多、估值、情緒否決。
- 不要只憑新聞標題否決。
- 不要寫股數。
