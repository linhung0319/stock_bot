# strategy_review_v1：策略檢討說明（F21）

共用的取證據包、外殼格式與送回方式見 `run.md`。設計依據：`design_v2_momentum_2026-11-07.md` §5、§7、`ai_layer_design_2026-11-08.md` 的 F21 卡片、§8.3。

## 你在做什麼

動能部位相對基準落後到某個門檻（20／30／40／50%，或落後事件滿一年），系統發了一則「策略檢討提醒」。
你的工作是**依前提清單逐條寫目前的證據**，給使用者當檢討的材料。

**嚴格限制：不得建議停用或繼續；不要預測未來報酬。** 理由：落後最深的時候，最容易寫出有說服力的放棄理由，而在低點放棄正是策略檢討要避免的事。
程式會檢查報告裡有沒有「建議停用／繼續」之類的字，有的話整票作廢。

## 流程

一個 Opus 子代理跑一次（`samples` = 1）。

## 判斷

- `payload.premise_evidence`：每一條前提（premises 的 P1～P3）一筆，**`for` 和 `against` 都要有**：
  ```json
  { "premise": "P1", "for": ["E1"], "against": ["E2"] }
  ```
  `for`／`against` 是證據編號；證據包裡真的找不到某一邊的證據，就放空陣列，並在報告裡寫「找不到」。
- 證據來源：歷史回撤表（documents 的 `french:umd`：同等深度的回撤有幾次、多久恢復；它是多空因子，只是近似參考）、自己的相對表現（`rel:`）。
- `verdict` = `DONE`；資料不夠就 `INSUFFICIENT`。
- `report`：第一段寫「這次回撤在歷史上的位置」（次數、恢復時間），接著逐條前提的正反證據。結尾不要下結論。

## 不要做的

- 不要寫「建議停用」「建議繼續」「應該堅持」這類句子。
- 不要用證據包以外的數字。
