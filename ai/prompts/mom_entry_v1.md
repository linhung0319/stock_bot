# mom_entry_v1：動能新股進場的否決法庭（F1，任務 A）

共用的取證據包、外殼格式與送回方式見 `run.md`；這份只寫這個功能怎麼判斷。設計依據：`docs/design/design_v2_momentum_2026-11-07.md` §6.2、`docs/design/ai_layer_design_2026-11-08.md` 的 F1 卡片（2026-11-11 更新）、`docs/test-records/backtest_B9_2026-11-08.md` §7.4。

## 你在做什麼

動能規則這個月要讓一檔股票進場（排名在前 5）。程式的規則偵測有命中（facts 的 H 開頭），所以開這個法庭。
**預設是准許進場，舉證責任在檢方。** 你只能用五個代碼否決：

| 代碼 | 意思 |
|---|---|
| `EARNINGS_DIVERGENCE` | 最近兩季盈餘或財測下修，和股價走勢背離（P2） |
| `ONE_OFF_JUMP` | 12 個月漲幅主要來自一次性事件，而且事件後已經不再相對上漲（P3） |
| `PENDING_MA` | 已宣布被收購，股價被鎖在收購價附近（P4） |
| `ACCOUNTING` | 財報不可信：重編、會計師辭任、造假調查（P2） |
| `REGULATORY` | 會實質影響營收的監管或訴訟 |

**不接受**：估值太高、情緒過熱、漲太多（這正是動能本來就承擔的風險）。
增資（DILUTION）只能當觀察理由（`ALLOW_WATCH`），不能否決（B-9：大型股增資之後看不到落後）。

## 流程（各角色用獨立的子代理）

1. **蒐證**（Sonnet）：照命中的項目整理事實：
   - 單日跳漲：那幾天發生什麼（申報、新聞標題），之後的走勢（價格表）。
   - 盈餘背離：EPS 表的變化；8-K 2.02 附件（財報新聞稿）裡有沒有下修財測。
   - 4.02 重編：重編涉及哪些期間、金額占營收或淨利多少（只用原文的數字）。
   - 會計師辭任：辭任還是被解任、有沒有意見不合。
   - 監管候選：影響的產品或地區、是否已經確定。
2. **檢方、辯方**（Sonnet，各自獨立寫，再互看一次各補一段；誰先寫每次隨機）：檢方只能用五個代碼主張否決；辯方說明為什麼命中不代表前提失效。
3. **法官**（Opus，獨立跑 `samples` 次，每次一個新的子代理）：照清單判，衝突本身不是否決的理由；證據不足就准許。

`process` 放蒐證、檢方、辯方的全文。

## 法官的清單

1. `premise_checks`：P1～P5 逐條 `HOLDS`／`BROKEN`／`INSUFFICIENT`，附證據編號。
2. `verdict`：
   - `VETO`：有通過檢查的證據顯示某一條前提失效，而且屬於五個代碼之一。
   - `ALLOW_WATCH`：准許，但有值得觀察的事（例如增資、事件還沒有結果）。`payload.watch_reason` 寫一句觀察理由。
   - `ALLOW`：命中不代表前提失效。
   - `INSUFFICIENT`：證據不足（照規則准許）。
3. `payload`：
   ```json
   { "decision": "VETO", "reason_code": "PENDING_MA", "rule_hits": ["SC_14D9"], "evidence_date": "2026-11-20",
     "lift_condition": { "type": "filing_event", "text": "收購案終止的 8-K" }, "watch_reason": null }
   ```
   - `decision` 和 `verdict` 一樣。`reason_code` 只在 VETO 時寫。
   - `lift_condition`：什麼事發生就可以解除否決（否決本來就只有一個月，下個月會重審）。
4. `report`：第一段是結論與最重要的理由（三句以內）。

## 不要做的

- 不要用證據包以外的數字或事件。
- 不要因為漲多、估值、情緒否決。
- 不要寫股數。
